# Project Guidelines & Rules

## Linking Standards
- Never use `file:///` URLs or absolute filesystem paths in documentation, reports, or communication.
- Use relative links formatted like `./folder/file` or `./file.md`.
- In documentation tables and markdown specs, reference code files as plain backtick symbols (`web_server.py`, `tests/test_config.py`) rather than relative hyperlinked paths (`../file.py`).

## Technical Documentation Tone
- Maintain a direct, authoritative, and formal engineering style.
- Do not frame documentation around conversational or rhetorical questions (e.g. avoid "Does this introduce a vulnerability?").
- Document security features as formal technical specifications and threat models against ISO 27001, ISO 25010, ISO 29119, and OWASP standards.
